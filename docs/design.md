# 《流明漂航》Game Studio 设计说明

## 玩家幻想

玩家不是战斗机驾驶员，而是一台脆弱但灵活的维修无人机。爽点来自“边躲危险边抢修系统”：路线规划、手感漂移、风险收集、连锁得分和波次升级。

## 玩家动词

- 漂移移动
- 短推进穿过危险区
- 跟随路线教练完成首局 4 步：补流明、修信标、躲危险、撤离升级
- 跟随导航提示选择下一目标
- 靠近信标并持续修复
- 释放脉冲推开碎片
- 收集流明补电并续连锁
- 执行本波战术合约，决定是否为了副目标绕路或保留技能
- 读取实时评级压力，知道当前是在保命、冲 A 还是冲 S
- 读取即时飘字和光环反馈，确认拾取、修复、受击和技能释放
- 读取维修光束、危险警戒圈和资源告警，判断下一秒是否安全
- 从北侧光门撤离
- 波次结束后选择升级
- 根据结算评级复盘路线质量
- 追踪成就挑战，选择下一局的自我目标
- 在三档难度中选择适合自己的压力曲线
- 读取救援代号，复盘或分享可复现的路线变体
- 根据救援区域读取新的信标、流明、碎片和风暴布局
- 根据本波事件调整路线和升级优先级
- 查看当前改装等级，并比较升级前后收益

## 核心循环

1. 选择难度：练习、标准或硬核决定电量、伤害、维修和分数倍率。
2. 入口：普通救援生成新代号；今日挑战用当天固定代号；历史日志和链接可以复现旧代号。
3. 代号：同一代号会复现轻微漂移后的信标、流明、危险源和风暴相位。
4. 读图：看本波救援区域、事件、信标、流明、风暴和碎片的位置；桌面端可扫右上角战术雷达判断路线密度和危险区。
5. 合约：读取本波战术合约，例如先捡 4 个流明、38 秒内修第一座信标、无损撤离、少进风暴或少用脉冲。
6. 教练：首局路线教练先引导玩家捡 2 个流明，再去信标、按住维修、撤离升级。
7. 补给：先捡金色流明，为修复保留电量。
8. 修复：靠近蓝色信标按 `E`，持续修复。
9. 决策：HUD 导航会提示补流明、修信标、撤离或脱离风暴，路线教练会在低电量、风暴和碎片贴脸时改成紧急提示。
10. 连锁：连续捡流明、修信标、撤离会提高倍率；HUD 会显示剩余连锁窗口，帮助玩家判断要继续抢分还是先保命。
11. 撤离：全部信标修好后，冲进北侧光门。
12. 成长：选择升级并进入更难波次，完成 5 波后通关本轮。

## 失败和胜利

- 机体归零：失败。
- 电量归零：失败。
- 全部信标修复并进入光门：当前波次胜利。
- 第 5 波进入光门：本轮救援完成。
- 被碎片击中：扣机体、扣电量、重置连锁。
- 进入风暴：持续扣电量，强迫玩家走位。

## 难度和发行层

- 练习：电量消耗和伤害更低，维修更快，分数倍率降低。
- 标准：推荐首次游玩，完整体验核心循环。
- 硬核：电量消耗和伤害更高，额外威胁更早出现，分数倍率提高。
- 救援区域：五波轮换不同空间布局，硬核模式会用更危险的区域顺序，避免每波路线都一样。
- 区域视觉：每个救援区域有独立的背景光网语言，例如外环环线、交叉航流、南弧补给带、风暴脊线和核心超频环，帮助玩家从画面直接感知空间变化。
- 救援代号：规则层生成可复现 `RoutePlan`，同一代号保持整轮五波的微布局变化，`?route=代号` 可复现路线，方便复盘和分享。
- 今日挑战：主菜单每天按本地日期生成固定救援代号，使用当前难度开局，并记录本地今日最佳，形成“当天同图复盘/冲分”的轻量长期目标。
- 任务档案：首屏用四个短信息块说明玩法类型、胜利条件、失败条件和成长循环，让玩家打开页面就知道这不是占位 demo。
- 第一分钟路线：开始按钮之后立刻给出“读图补电、贴近维修、保命续分、撤离升级”四步，让玩家第一次滚动时看到可执行路线，而不是只看到系统名词。
- 下一局目标看板：菜单和结算从当前存档、今日挑战、上一局结果和未完成成就里派生 4 个短目标，让玩家知道下一局该追首座信标、第一波撤离、合约、今日最佳、硬核或 S 级。
- 波次事件：五波会依次改变战场规则，例如流明回电更多、碎片更快、风暴更强、维修更快但耗电更紧。
- 战术合约：每波给出一个中文副目标，完成后即时加分、触发反馈、写入结算；过关但没达成会明确标为失败。
- 合约目标标记：规则层输出当前合约的战场焦点，Phaser 可读性层用低遮挡光环标出相关流明、信标、碎片或风暴。
- 波次开场简报：进入每波时用低遮挡 DOM 提示当前区域、波次事件和战术合约，几秒后收起，避免玩家开局不知道要读什么。
- 开局读图缓冲：每波开始后直到第一次移动、修复、推进或脉冲前，不推进计时、不耗电、不结算碰撞和风暴，让玩家能先读中文目标、雷达、合约和场面。
- 实时评级：规则层用信标进度、合约、连锁、受击、风暴、电量、速度和流明收集生成局内 `S/A/B/C` 压力条，并给出下一步提分建议。
- 连锁窗口：规则层统一控制连锁持续时间，HUD 以进度条展示剩余窗口，窗口结束后倍率回到 1.0x。
- 本地存档：记录最佳分数、最远波次、最佳连锁、单轮最佳合约数和今日挑战最佳。
- 可访问性设置：本地保存精简动效和大字标签；精简动效减少屏幕抖动、粒子尾迹和 HUD 过渡，大字标签提升画布物件标签与关键信息可读性。
- 航行日志：本地保存最近 5 次救援摘要，菜单和结算展示最近路线、评级、分数、波次和合约状态，并支持一键重跑同一救援代号，帮助玩家复盘与重试。
- 成就挑战：本地记录第一束光、无损撤离、流明猎手、S 级信号、全域稳定和硬核光网，给玩家明确的长期目标。
- 升级摘要：规则层生成当前效果和下一等级效果，HUD 与升级卡共用，避免成长反馈含糊。
- 局内任务条：规则层输出当前目标，DOM HUD 将其整理为“当前任务/紧急任务/维修任务/撤离任务”，并带上波次、信标、救援代号和合约进度。
- 底部任务文本：DOM HUD 优先使用当前目标和当前危险生成短句，避免最近事件消息在状态变化后残留成过期警报。
- 局内导航：规则层输出当前目标，DOM HUD 显示中文提示，Phaser 画布显示导引线和目标光环。
- 路线教练：规则层输出 `CoachDirective`，DOM HUD 显示当前步骤、原因和进度；开局先解释读图缓冲，Phaser 画布同时用虚线路径和编号标出首段“补流明 → 修信标”路线，之后导航线优先指向教练目标，确保首局不会一开场就把玩家带去硬修信标。
- 战术雷达：Phaser 场景把玩家、信标、流明、危险源、风暴和光门位置输出给 DOM HUD，桌面端用小地图帮助玩家快速读图，窄屏自动隐藏以保护游玩区域。
- 暂停战术扫描：暂停/玩法说明复用最新雷达快照，在覆盖层展示更大的路线图，让桌面和手机玩家都能安全复盘当前目标与危险。
- 结算复盘：每次胜利、通关或失败后展示分数、波次、用时、最佳连锁、流明、信标、受击和风暴停留。
- 结算评级：每局按通关状态、连锁、受击、风暴暴露、速度、流明收集和剩余电量生成 `S/A/B/C` 中文评级。
- 下一局建议：根据电量归零、机体损毁、风暴停留、拾取不足或碰撞过多给出中文指导。
- 即时反馈：画布中用短暂飘字和扩散光环标出拾取、修复、推进、脉冲、受击、撤离和失败，避免玩家只看 HUD 数字。
- 可读性反馈：规则层输出合约焦点、维修锁定、资源告警和碎片危险等级；画布用合约光环、移动碎片轨迹预警、维修光束、警戒圈和无人机周围告警环表现，HUD meter 同步低资源状态。
- 音效：网页音频合成短音，反馈推进、拾取、修复、受击、胜利和失败。

## 升级

- 矢量引擎：提高推力，缩短推进冷却。
- 信标织机：加快修复，提高信标得分。
- 深层电容：提高最大电量，流明回复更多。
- 棱镜脉冲：扩大脉冲范围，推开碎片更远。
- 曜盾机体：提高机体上限，降低碰撞伤害。

## UI 设计

- Phaser canvas：游戏世界、无人机、信标、流明、碎片、风暴和光门。
- Phaser sector backdrop：按当前救援区域绘制不同的城市光网纹理、航道、环线和核心结构，提升波次辨识度和成品感。
- Phaser feedback layer：短时文字、光环、震动和粒子用于奖励、危险和状态变化。
- Phaser readability layer：开局路线预览、画布维修按键提示、维修光束、合约目标标记、危险预警、低资源环，专门服务战斗/路线判断。
- Phaser accessibility layer：响应 DOM 设置事件，精简动效时关闭抖动和粒子尾迹，大字标签时重建战场标签。
- DOM HUD：中文状态、局内任务条、分数、连锁、连锁窗口、技能状态、实时评级、当前改装、当前救援区域、当前波次事件、战术合约和当前导航提示。
- DOM control copy：关键动作说明同时写键盘键位和触控动作名，例如 `E / 修复键`、`Space / 推进键`、`Q / 脉冲键`，避免手机和平板玩家看到只属于键盘的提示。
- DOM wave intro：每波开场短暂提示区域、事件和合约，作为读图入口而不是常驻遮挡。
- DOM route：HUD 目标详情和结算指标显示救援代号，让玩家知道这轮路线可以复现。
- DOM coach：局内显示紧凑路线教练，正常状态解释下一步，紧急状态提示脱离风暴、用脉冲或先补电。
- DOM radar：桌面右上角显示战术雷达、目标数量和图例，让玩家不用暂停也能判断信标、流明、碎片、风暴和光门的大致关系。
- DOM tactical scan：暂停层显示当前路线扫描图和同一套图例，给手机端和需要停下来思考的玩家一个不遮战场的读图入口。
- HUD 披露策略：菜单和结算展示完整成绩与说明；进入游玩后隐藏记录条和长消息，压缩统计、合约和导航提示，避免左侧面板吃掉过多战场视野。
- DOM overlay：中文主菜单、任务档案、首屏核心循环简报、战场图例、下一局目标看板、难度选择、今日挑战与今日最佳、音效开关、成就挑战、最近航行日志、日志重跑路线、玩法说明、暂停、胜负复盘、合约结果、评级、成就解锁、下一局建议、升级选择、路线链接复制、同代号重开和本地存档二次确认清空。
- Canvas readability：关键对象保留中文物件标签，蓝色信标、金色流明、粉色碎片、紫色风暴和北侧光门在战场上可直接识别。
- 触控设备：粗指针或无 hover 的设备显示触控摇杆、三个动作按钮和独立暂停按钮，不能只依赖 `max-width` 判断；触控游玩态隐藏常驻右上雷达，改用暂停战术扫描读图，避免暂停按钮和雷达互相遮挡；游玩态进一步收起品牌、波次说明、改装条和长说明，把评级、合约和教练压成短状态，优先保留资源、目标、触控和战场视野。触控控件必须捕获当前指针、禁用浏览器默认触摸手势，并在暂停、失焦、页面隐藏或指针丢失时清空虚拟输入。
- 键盘输入保护：开始新局、重跑路线、进入暂停和继续游玩时，Phaser 键盘状态必须清空，防止玩家按住移动、修复或推进打开菜单后恢复时残留旧输入。
- 自动安全暂停：窗口失焦、页面隐藏或页面离开时，DOM 控制层清空虚拟输入并把正在游玩的救援切到暂停说明层，显示“已自动暂停”和战术扫描，防止玩家看不到游戏时继续耗电、受击或保留按键状态。

## 验收标准

- 玩家打开页面能立刻知道“这是什么游戏、目标是什么、怎么操作”。
- UI 文案为中文，英文只作为副标题或技术名保留。
- 首屏必须明确说明玩法类型、胜利条件、失败条件和成长循环，避免玩家觉得只是未说明的技术 demo。
- 首屏必须提供第一分钟可执行路线，玩家不读文档也能知道开局先捡流明、再修信标、再撤离。
- 开局读图缓冲期间，战场画布必须把首段路线直接画出来，不能只依赖 HUD 文案解释第一步。
- 手机首屏必须在不滚动的情况下露出主要开始动作；详细玩法图例和下一局目标可以放在按钮之后。
- 首屏和战场画布必须能解释主要颜色/物件含义，避免玩家把图形当作未汉化占位符。
- 关键动作提示必须同时覆盖键盘和触控；玩家靠近信标时，画布必须出现维修提示，不能只在 HUD 或说明书里写 `E`。
- 移动碎片必须有低遮挡方向/轨迹预警，玩家需要能提前判断切线，而不是被看不出方向的抽象物体突然撞到。
- 每波开始后，玩家第一次输入前必须能安全读图，不应因为看波次简报、合约或暂停说明而被后台耗电、撞击或计时惩罚。
- 不同救援区域必须有可见的背景差异，玩家不应感觉五波只是同一张抽象底图换坐标。
- 首屏和结算必须给出下一局目标或修正重点，让玩家知道为什么要再开一局。
- 局内 HUD 在桌面和移动端都必须保护中心与下方游玩区域，不把菜单式记录或长说明常驻在战场上；手机战斗态不应让合约/教练长文案挤压触控操作区。
- 触控输入必须可靠：手机、平板横屏和其他粗指针设备都必须有摇杆与动作按钮；摇杆拖动不能触发浏览器默认滚动或选中文本，动作按钮必须有按下态反馈，暂停、失焦和丢失指针捕获后不能留下移动、修复、推进或脉冲的虚拟输入。
- 键盘输入必须可靠：开始、暂停、自动暂停、继续、重跑路线和进入下一波都不能继承上一状态残留的移动、修复、推进或脉冲按键。
- 自动安全暂停必须可靠：游玩态窗口失焦、页面隐藏或 pagehide 后必须清空输入、暂停模拟、显示中文原因和战术扫描；菜单、结算和已经暂停的状态不能被误切成新局暂停。
- 桌面战术雷达必须在游玩态显示路线/危险关系，并且不能和左侧 HUD、中央目标条或手机触控区重叠；窄屏和手机战斗态必须隐藏雷达。
- 粗指针触控设备即使宽度超过手机断点，也必须隐藏桌面雷达并保留暂停战术扫描入口，避免右上暂停按钮覆盖雷达。
- 暂停/玩法说明必须能显示当前战术扫描图，帮助玩家在不操作的状态下复盘路线，且不会替代战斗中的低遮挡 HUD 策略。
- 冲分信息必须可读：实时评级和连锁窗口要让玩家知道下一步该续连锁、做合约还是先保命。
- HUD 文案必须可信：玩家离开风暴、进入维修或切换到补给目标后，底部任务文本不能继续显示过期危险或旧事件。
